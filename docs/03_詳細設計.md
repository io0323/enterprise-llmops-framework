### 2.1 Observability

```sql
-- 論理的な1処理単位(記事1本の生成、DDEの1ラン、Harnessの1パイプライン実行)
CREATE TABLE IF NOT EXISTS traces (
    id            TEXT PRIMARY KEY,          -- UUID4
    system        TEXT NOT NULL,             -- 'cgmp' / 'dde' / 'harness' / 'elf'
    operation     TEXT NOT NULL,             -- 'article.generate' / 'topic.classify' 等
    external_id   TEXT,                      -- 呼び出し元のID(CGMPのrequest_id等)
    status        TEXT NOT NULL DEFAULT 'running', -- running/success/partial/failed
    started_at    TIMESTAMP NOT NULL,
    finished_at   TIMESTAMP,
    meta_json     TEXT                       -- 任意の付帯情報
);
CREATE INDEX IF NOT EXISTS idx_traces_system   ON traces(system, started_at);
CREATE INDEX IF NOT EXISTS idx_traces_external ON traces(external_id);

-- LLM呼び出し1回。FR-030/031/032 の中核
CREATE TABLE IF NOT EXISTS spans (
    id                TEXT PRIMARY KEY,
    trace_id          TEXT NOT NULL REFERENCES traces(id) ON DELETE CASCADE,
    parent_span_id    TEXT REFERENCES spans(id),
    seq               INTEGER NOT NULL,      -- trace内の連番
    task              TEXT NOT NULL,         -- 'outline'/'section'/'closing'/'judge' 等
    -- 資産の刻印(FR-032): これが無いと再現不能
    prompt_id         TEXT,
    prompt_version    INTEGER,
    render_hash       TEXT,                  -- レンダリング後テキストのSHA-256(先頭16桁)
    logical_model     TEXT NOT NULL,         -- 'chat-standard' 等
    model_version     INTEGER,
    adapter           TEXT NOT NULL,         -- 'claude_cli'/'anthropic_sdk'/'mock'
    resolved_target   TEXT,                  -- Adapterが実際に使った識別子(コマンド/モデル名)
    -- 入出力(絶対ルール: 全文記録)
    request_text      TEXT NOT NULL,
    response_text     TEXT,
    raw_response_json TEXT,                  -- Adapterの生応答(metaごと保存)
    -- 実行結果
    success           INTEGER NOT NULL,
    degraded          INTEGER NOT NULL DEFAULT 0,  -- Fallbackで得た結果か
    billable          INTEGER NOT NULL DEFAULT 1,  -- 1=実課金, 0=サブスク換算(§2.4)
    attempt           INTEGER NOT NULL DEFAULT 1,
    error_type        TEXT,
    error_message     TEXT,
    -- 計測(FR-031)
    duration_ms       INTEGER,
    api_duration_ms   INTEGER,
    input_tokens      INTEGER,
    output_tokens     INTEGER,
    cache_read_tokens INTEGER,
    cache_write_tokens INTEGER,
    cost_usd          REAL,
    num_turns         INTEGER,
    provider_session  TEXT,                  -- claude -p の session_id 等
    created_at        TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX IF NOT EXISTS idx_spans_trace  ON spans(trace_id, seq);
CREATE INDEX IF NOT EXISTS idx_spans_prompt ON spans(prompt_id, prompt_version);
CREATE INDEX IF NOT EXISTS idx_spans_date   ON spans(created_at);
```

**設計理由**: `raw_response_json` を丸ごと残すのは、Adapterの応答スキーマがProvider側の更新で変わりうるため。構造化カラムのパースに失敗しても生データから後で再集計できる。

```sql
    logical_model TEXT NOT NULL,

    input_tokens  INTEGER NOT NULL DEFAULT 0,
    output_tokens INTEGER NOT NULL DEFAULT 0,
    cost_usd   REAL NOT NULL DEFAULT 0,
```

`cost_daily` は `spans` からの導出だが、予算判定を毎回フルスキャンさせないための集計テーブル。span記録時に同一トランザクションでUPSERTする。

#### 実課金とサブスク換算を分ける(`billable`)

`budgets` が判定に使うのは **`billable = 1` のコストだけ**。

| コストの性質 | 例 | `billable` | 予算 | 記録・レポート |
|---|---|---|---|---|
| 実課金 | `anthropic_sdk`(Harness) | 1 | **対象** | 載る |
| サブスク換算 | `claude_cli` の `total_cost_usd`(CGMP/DDE) | 0 | 対象外 | 載る |
| 無課金 | `mock` | 0 | 対象外 | 載る |

`claude -p` のコストはサブスク利用の換算値で、追加の請求は発生しない。これを予算に混ぜると、**課金していない処理が、課金している処理を止める**(CGMPが1記事あたり約0.67 USDを計上するため、月30記事で global 20 USD に到達し、その時点で実課金しているHarnessまで止まる)。判定対象を分けることでこれを避ける(NOTES.md N-045)。

`billable` は `models.yaml` の論理モデルごとに宣言する。未宣言のときは adapter から決まり、**既定は `true`(課金される側)**。宣言を忘れたモデルが黙って予算を素通りする、という失敗の向きを塞ぐため。

サブスク換算コストに上限を設けたくなった場合も、`budgets` には混ぜない。意味が違う数字を同じテーブルで比較すると、どちらの上限に当たったのか判らなくなる。必要になった時点で別枠として設計する。

## 3. Prompt ファイル形式

`prompts/<system>/<name>.md`。prompt_id は パス から導出(`prompts/cgmp/section.md` → `cgmp.section`)。

```markdown
---
id: cgmp.section
version: 3
status: published
owner: io
description: CGMPの本文セクション生成
tags: [cgmp, writer, rag]
model: chat-standard          # 既定の論理モデル(呼び出し側で上書き可)
eval_suite: cgmp-section
includes: [no_hallucination, context_rule, style_rules]   # §3.1 fragment
variables:
  type: object
  required: [title, section_heading, context, terminology]
  properties:
    title:            {type: string, minLength: 1}
    section_heading:  {type: string}
    context:          {type: string}
    terminology:      {type: array, items: {type: string}}
    max_chars:        {type: integer, default: 1200}
constraints:
  # 絶対ルール9(CGMP)をPrompt側のメタデータとして宣言し、
  # 決定的評価がこの宣言を根拠に検証する
  require_grounding: true
  forbid_outside_context: true
---

あなたは技術記事のセクションを書くライターです。

# 対象記事
{{ title }}

# 担当セクション
{{ section_heading }}

# 参照可能な事実(context)
{{ context }}

# 制約
{{ include.no_hallucination }}
{{ include.context_rule }}
- 用語は次に従う: {{ terminology | join(", ") }}
- {{ max_chars }}字以内

{{ include.style_rules }}
```

### 3.1 Fragment(共有ルール断片)

CGMPの調査で、複数Promptから参照される固定ルール文字列が**7件**(`NO_CONTEXT` / `CONTEXT_RULE` / `NO_HALLUCINATION_RULE` / `TIME_SENSITIVE_RULE` / `PROMOTION_RULE` / `EXCEPTION_RULE` / `STYLE_RULES`)存在することが判明した。これを各Promptへ複製すると、ルール1つの修正が3ファイルの同時編集になり、Prompt外部化の利益が消える。よってfragmentを導入する。

```
prompts/
├── _fragments/
│   ├── no_hallucination.md
│   ├── context_rule.md
│   ├── style_rules.md
│   └── ...
├── cgmp/
│   ├── outline.md
│   └── section.md
└── dde/
```

front matter で宣言し、本文から `{{ include.<name> }}` で参照する。

```yaml
includes: [no_hallucination, context_rule, style_rules]
```

```markdown
# 制約
{{ include.no_hallucination }}
{{ include.context_rule }}
```

**制約**(意図的に機能を絞る):

- fragment は**ネストしない**(fragment の中で `{{ include.x }}` を書けない)。1段のみ
- fragment に変数を渡せない。パラメータが要るもの(`term_rule()` / `tone_rule()` のような
  引数依存のテキスト)は fragment にせず、**呼び出し側で組み立てて通常の変数として渡す**
- `content_hash` の計算に**展開後のテキスト**を含める。fragment を変更すると、
  それを参照する全Promptに新versionが採番される(変更が版として残ることの保証)
- fragment 自身も `prompt_versions` に `prompt_id='_fragments.<name>'` として登録し、版管理する

### 3.2 レンダリング仕様

- テンプレート構文: `{{ var }}` と `{{ var | filter }}` のみ。制御構文(if/for)は**持たない**
  - 理由: ロジックがPromptに入ると、変更影響がテストで追えなくなる。分岐が必要な場合はPromptを分ける
  - 実装: Jinja2を使わず自前の最小レンダラ(正規表現ベース)。依存を増やさず、構文を意図的に制限するため
- フィルタは `join(sep)` / `default(v)` / `upper` / `trim` のみ
- 未定義変数は `MissingVariable` を送出(空文字で黙って通さない)
- `render_hash` = SHA-256(レンダリング後テキスト)の先頭16桁。PEPの `renderHash` と同じ定義

## 4. models.yaml 形式

```yaml
models:
  chat-standard:
    adapter: claude_cli
    params:
      command: ["claude", "-p", "--output-format", "json"]
      timeout_sec: 600
    price:
      input_per_1k: 0.0     # claude -p はサブスク実行のため0。実コストはspanのcost_usdを正とする
      output_per_1k: 0.0
    # fallback_to は設定しない。Fallback 機構自体は Gateway にあるが(FR-014)、
    # 落とし先が mock だと「それらしい偽の結果」が通る(NOTES.md N-026)。
    # 本物の代替 Provider ができるまで、本番の論理モデルでは有効にしない

  chat-fast:
    adapter: claude_cli
    params:
      command: ["claude", "-p", "--output-format", "json"]
      timeout_sec: 180

  judge:
    adapter: claude_cli
    params:
      command: ["claude", "-p", "--output-format", "json"]
      timeout_sec: 300

  chat-fallback:
    # Fallback 機構そのものの動作確認用。**本番モデルの fallback_to には指定しない**
    adapter: mock
    params:
      mode: echo

  # Harness用(optional extra が入っている環境のみ有効)
  # Agent ごとに harness-generator / harness-evaluator / harness-learning を置く(NOTES.md N-044)
  harness-generator:
    adapter: anthropic_sdk
    billable: true                  # 実課金。予算(budgets)の対象(§2.4 / N-045)
    params:
      model_env: MODEL_GENERATOR      # モデル名は環境変数から。コードとYAMLに実モデル名を書かない
      max_tokens: 1024                # Harness の既存呼び出しを踏襲
    price:                            # 単価は models.yaml に書く(環境変数での上書き機構は無い)
      input_per_1k: 0.003
      output_per_1k: 0.015
```

**Vendor Neutral 方針**: APAPの規約(「コード・設定・コメントに特定AI Provider名/製品名/モデル名を書かない」)に合わせ、実モデル名は環境変数経由で解決する。Adapter名(`anthropic_sdk`)は実装モジュール名なので例外とする。

### 5.1 SDK(利用システムが import する唯一の入口)

```python
# llmops/sdk/client.py
from dataclasses import dataclass
from typing import Any, Mapping

@dataclass(frozen=True)
class CompletionResult:
    text: str
    span_id: str
    prompt_id: str | None
    prompt_version: int | None
    logical_model: str
    input_tokens: int | None
    output_tokens: int | None
    cost_usd: float | None
    duration_ms: int
    degraded: bool
    raw: dict[str, Any]

class LLMOps:
    """利用システムが持つ唯一のELFハンドル。"""

    @classmethod
    def load(cls, config_path: str | None = None, *, system: str) -> "LLMOps": ...

    def trace(self, operation: str, external_id: str | None = None,
              **meta: Any) -> "TraceContext":
        """with 構文で使う。抜けると finished_at と status が確定する。"""

    def complete(
        self,
        *,
        prompt_id: str,                 # 'cgmp.section'
        variables: Mapping[str, Any],
        model: str | None = None,       # 省略時はPrompt front matterの model
        task: str | None = None,        # 省略時は prompt_id の末尾
        version: int | None = None,     # 省略時は published(canary考慮)
        as_json: bool = False,
        retry: bool | None = None,
    ) -> CompletionResult: ...

    def complete_raw(self, *, text: str, model: str, task: str) -> CompletionResult:
        """Registry管理外のアドホック呼び出し。監査ログに記録され、既定では無効。
        config の allow_raw_completion: true が必要(移行期間のみ有効にする)。"""
```

### 5.2 互換shim(FR-013 / 移行用)

既存 `cgmp/llm/client.py` の `LLMClient` と**同一シグネチャ**。CGMP/DDEの移行差分をimport文だけにする。

```python
# llmops/sdk/compat.py
class LLMClient:
    """既存 cgmp.llm.client.LLMClient / dde.llm.client.LLMClient のドロップイン代替。

    差分:
      - prompt文字列を直接受け取る呼び出しは、prompt_id 未指定のadhoc spanとして記録される
      - call_json / call_text / ensure_budget / calls_used / remaining_calls を同名同挙動で提供
      - 呼び出し回数上限(CGMP絶対ルール3)は ELF の Guard が担う
    """
    def __init__(self, config, repo=None, *, system: str, ops: "LLMOps | None" = None): ...
    def call_json(self, prompt: str, task: str,
                  request_id: str | None = None, section_seq: int | None = None) -> Any: ...
    def call_text(self, prompt: str, task: str, request_id: str | None = None,
                  section_seq: int | None = None, retry: bool = True) -> str: ...
    def ensure_budget(self, request_id: str, needed: int = 1) -> None: ...
    def calls_used(self, request_id: str) -> int: ...
    def remaining_calls(self, request_id: str) -> int: ...
```

既存の例外階層も維持する: `LLMError` / `LLMBudgetExceeded`(ELFでは `QuotaExceeded` のサブクラスとして再輸出)。

### 5.3 Provider Adapter SPI

```python
# llmops/adapters/base.py
from abc import ABC, abstractmethod
from dataclasses import dataclass, field
from typing import Any

@dataclass
class AdapterRequest:
    text: str
    params: dict[str, Any] = field(default_factory=dict)

@dataclass
class AdapterResponse:
    text: str
    raw: dict[str, Any]
    input_tokens: int | None = None
    output_tokens: int | None = None
    cache_read_tokens: int | None = None
    cache_write_tokens: int | None = None
    cost_usd: float | None = None
    api_duration_ms: int | None = None
    num_turns: int | None = None
    session_id: str | None = None
    resolved_target: str | None = None

class ProviderAdapter(ABC):
    name: str

    @abstractmethod
    def invoke(self, req: AdapterRequest) -> AdapterResponse: ...

    def health(self) -> bool:
        return True
```

Adapterは**Registry・DB・Gatewayを一切importしない**。テスト時に単体で差し替えられることを保証する。

### 5.4 claude_cli Adapter の実装要点

`claude -p --output-format json` の応答から、現在DDE/CGMPが捨てている情報を全て拾う(FR-031)。

```python
# 応答JSONから拾うフィールド(存在しないものはNoneのままにし、KeyErrorで落とさない)
payload = json.loads(completed.stdout)
resp = AdapterResponse(
    text            = str(payload["result"]),          # 既存実装と同じ。ここだけは必須
    raw             = payload,                         # 丸ごと保存(§2.1の設計理由)
    cost_usd        = payload.get("total_cost_usd"),
    api_duration_ms = payload.get("duration_api_ms") or payload.get("duration_ms"),
    num_turns       = payload.get("num_turns"),
    session_id      = payload.get("session_id"),
    input_tokens    = (payload.get("usage") or {}).get("input_tokens"),
    output_tokens   = (payload.get("usage") or {}).get("output_tokens"),
    cache_read_tokens  = (payload.get("usage") or {}).get("cache_read_input_tokens"),
    cache_write_tokens = (payload.get("usage") or {}).get("cache_creation_input_tokens"),
    resolved_target = " ".join(command),
)
```

**重要**: 応答スキーマはCLIのバージョンで変わりうる。**必須は `result` のみ**とし、他は `.get()` で欠損許容する。欠損時はWARNログを出すが処理は継続する。`is_error: true` / 非ゼロ終了コードは失敗として扱う(既存実装の判定を踏襲)。

コードフェンス除去(`strip_fence`)とJSON抽出(`extract_json`)は既存 `cgmp/llm/client.py` の実装を**そのまま移植**する。実績があり、挙動差分が回帰の原因になるため改善しない(改善は Phase 2 以降に評価付きで行う)。

## 6. Gateway 処理詳細

```python
def complete(self, req: CompletionRequest) -> CompletionResult:
    # 1. Prompt解決(published以外は拒否。canary割合に従い版を選択)
    pv = self.prompts.resolve(req.prompt_id, version=req.version)
    if pv.status != "published" and not self.config.allow_unpublished:
        raise PromptNotPublished(req.prompt_id, pv.version, pv.status)

    # 2. 変数検証 → レンダリング
    text, render_hash = self.prompts.render(pv, req.variables)

    # 3. モデル解決
    mv = self.models.resolve(req.model or pv.default_model)

    # 4. Guard(Hard Quota。呼び出し前に判定する)
    self.guard.check(system=self.system, model=mv, estimated_cost=self.cost.estimate(mv, text))

    # 5. 実行(retry → fallback)
    for attempt in range(1, self.retry_max + 1):
        span = self.tracer.start_span(...)            # 開始時点で記録
        try:
            resp = self.adapters[mv.adapter].invoke(AdapterRequest(text, mv.params))
            body = extract_json(resp.text) if req.as_json else strip_fence(resp.text)
            self.tracer.end_span(span, resp, success=True)   # best-effort
            self.cost.accrue(span, resp)
            return CompletionResult(...)
        except Exception as exc:
            self.tracer.end_span(span, None, success=False, error=exc)
            last = exc
    # 6. Fallback(1段のみ。多段Fallbackは無限連鎖の危険があるため禁止)
    if mv.fallback_to and not req.no_fallback:
        return self.complete(replace(req, model=mv.fallback_to, no_fallback=True))._degraded()
    raise LLMError(...) from last
```

**設計上の固定判断**:
- span は**呼び出し前に開始行をINSERT**する。プロセスが落ちても「呼び出そうとした」記録が残る
- Fallbackは**1段のみ**。`no_fallback=True` を付けて再帰することで連鎖を構造的に防ぐ
- Guardは**呼び出し前**に判定する。事後判定では予算超過を止められない(19章 §13)
- Tracer の書き込み例外は捕捉してログ出力のみ(NFR-02)。ただし `ELF_STRICT_TRACE=1` のときは送出(テスト用)

## 9. テスト方針

| 種別 | 対象 | 方針 |
|---|---|---|
| 単体 | render / resolver / retry / cost計算 / 状態機械 | 純関数として検証。LLM呼び出しなし |
| Adapter | claude_cli | `subprocess.run` をモック。**実APIを叩くテストを書かない**(CGMP規約継承) |
| 統合 | Gateway一連 | `mock` Adapterで実行し、spans/traces/cost_dailyの中身を検証 |
| 回帰 | render_hash決定性 | 同一入力→同一hash。PEP `tests/prompt-regression` と同方式 |
| 互換 | compat.LLMClient | 既存CGMPテストのLLMClient差し替え版が通ること |
| 規約 | ハードコードPrompt検出 | `tests/test_no_hardcoded_prompts.py` が対象リポジトリを走査し、長い文字列定数を検出したら失敗 |

カバレッジ目標: `gateway` / `prompt` / `registry` は行カバレッジ80%以上(APAPの `koverVerify` 基準に合わせる)。

## 10. エラー階層

```

├── PromptError
│   ├── PromptNotFound
│   ├── PromptNotPublished
```

既存コードは `LLMError` / `LLMBudgetExceeded` を捕捉しているため、この2つは**名前・捕捉可能性ともに維持**する。
